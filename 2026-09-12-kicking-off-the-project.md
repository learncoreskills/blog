# Day 1: kicking off the project

Today marked the actual start of the project: a GitHub organization for it, and two repositories
underneath — `specs`, to hold requirements and technical specs, and `blog`, this running story of
what gets built, one entry per day.

Before writing any code, the time went into the basics: what the product actually is (a practice
app to help kids build core skills, starting with mental math), how the specs repo should be
organized (one folder per feature, plus a light set of product and architecture notes), and a
first rough set of requirements to build from. Nothing was implemented yet — the goal for day one
was making sure everything that comes next has a clear place to live and a plan to follow.
